# 真实 LTP、7350 Hz 与 DRC 预测历史修复（2026-10-30 p1）

本轮补齐了 **7350 Hz 实际启用长期预测的有声验证**，并修复原版及此前重建版共有的 **LTP + DRC 增益反馈**。修复位于 `cmake/faad2_ltp_drc_compat.cmake`；只作用于固定 FAAD2 2.11.4 的构建副本，不改变原 AddIn 工厂、方法布局及 XP／Win7 构建方式。

LTP960 的前向变换修复、合法配置初始化已在上一轮完成，但仍缺可信的真实有声码流。此次没有修改帧长标志或把 LC960 改名冒充真实 LTP960。

## 1. 找到可用编码器的方法

当前本机 FFmpeg 9.x 的 AAC 编码器已移除 Main/LTP 编码。`-strict -2` 不能恢复已经删除的代码；[FFmpeg 官方提交记录](https://ffmpeg.org/pipermail/ffmpeg-cvslog/2025-February/147287.html) 对应提交 `938353377068f3bcb874673b65e75367e0142aff`。

先在私有目录下载并运行 FFmpeg 7.1.1，使用真实编码参数：

```text
-c:a aac -aac_ltp 1 -aac_coder twoloop -aac_pns 0 -strict -2
```

7350／8000／48000 Hz、单／双声道的六个文件都是真正的 AOT 4 编码输出，完整 PCM 与独立解码器一致，但对实际执行 `ltp.data_present` 的计数全部为零。改变质量参数后的补充文件也没有启用预测。因此不能仅凭文件声明 `LTP` 就把它们计为长期预测算法验证。

随后以 [FAAC 官方历史标签 faac1_28](https://github.com/knik0/faac/tree/faac1_28) 的公开 API 实际编码，没有修改编码器源码。固定下载 ZIP SHA256：

```text
13c461d2f30be9f7c4423bb62b3c8ea8f750a66f32c68d35a69b7cd06c5894da
```

选择 MPEG-4、LTP、1024 帧、16 位输入；每声道低率 24 kbit/s、48 kHz 为 64 kbit/s。该旧编码器的 TNS 分支曾产生超过该对象类型限值的阶数并被独立解码器拒绝，最终向量通过其正常 API 关闭 TNS。未修改插件去接受这种编码器错误。

FAAC 1.28 的频率索引只到 8 kHz。7350 Hz 向量由其有效 8 kHz 有声码流作**同频带表族的时钟变换**：只把 ASC 频率索引 11 改为 12，所有实际编码包、预测参数及 1024 帧长保持不变。此项明确属于基于规范频带关系的构造向量，不称为“FAAC 原生 7350 Hz 编码”。ASC 另外显式声明无 SBR，避免旧低频率隐式升采样猜测。

FFmpeg 9.x 可以独立解码这两个真实 7350 Hz 容器；以实际 7350 Hz 声明解码得到的完整 PCM 与同包 8 kHz 参考逐位相同，时间长度则随真实时钟变化。没有仅改 WAVE 声明或把 7350 谎报为 8000。

所有编码器、下载、输入、包、PCM、探针及日志只保留在 `rebuild/tests/plugins_followup_20261030p1/aac-ltp/`，不上传仓库，不进入 Action 或发行包。

## 2. 实际启用预测的独立 PCM 对照

编码输入为约四秒的确定性多音、包络变化和间歇片段。以下六个最终文件中的预测确实被使用。计数由私有只读诊断构建记录 `ltp.data_present`；官方 `ap05_48` 也用于确认计数探针不是失效的零计数。

| 时钟／声道 | 输出帧数 | 实际预测调用 | 最大浮点误差 | RMS 浮点误差 |
|---|---:|---:|---:|---:|
| 8000 Hz／1 | 32768 | 26 | 0.000047088 | 0.000007789 |
| 7350 Hz／1 | 32768 | 26 | 0.000047088 | 0.000007789 |
| 8000 Hz／2 | 32768 | 52 | 0.000054747 | 0.000007528 |
| 7350 Hz／2 | 32768 | 52 | 0.000054747 | 0.000007528 |
| 48000 Hz／1 | 192512 | 177 | 0.000092082 | 0.000011822 |
| 48000 Hz／2 | 192512 | 50 | 0.000018261 | 0.000000878 |

独立参考为 FFmpeg 9.x 解码输出；这六个向量不需要对齐裁剪，双方输出总帧数相同。FAAD 使用 16 位长期预测历史，不能要求与浮点历史实现逐位相等；本组最大误差低于 3.1 个 16 位 LSB、RMS 低于 0.4 LSB。未拟合音量或平移波形来掩盖误差。原 no-DRC PCM 在本次修复前后逐位不变。

本组不以 PNS 噪声序列的跨实现逐位相等作为正确性条件。FAAC 最终向量采用实际有声频谱及长期预测；通用 DRC 修复直接复用已经完成 PNS／预测／TNS 的频谱，不再次运行 PNS 或推进随机数状态。

## 3. LTP + DRC 的根因与修复

旧流程先对频谱执行 DRC，再作 IMDCT，随后把带输出增益的 `time_out` 和 overlap 写入 `lt_pred_stat`。下一个包把这个被放大／衰减的历史用于长期预测；误差随预测继续累积。

不能只把 `lt_update_state` 向前移动：当前频谱已经被改动，上一帧 overlap 也可能已经带增益。修复在首次对该声道应用 DRC 时保存独立的、未施加增益的 overlap，此后：

1. 在 DRC 之前，以原频谱及独立 overlap 生成无增益的合成结果，更新长期预测历史。
2. 按既有流程应用 DRC 并合成用户输出，保留正确的增益切换重叠。
3. 跳过原来从输出更新历史的步骤。独立 CCE 时域混合仍在历史更新之后，避免把耦合输出反馈进目标声道预测。

普通没有 DRC 的 LTP 不增加内存分配或额外 IMDCT。曾经启用 DRC 的声道保留无增益 overlap，直至该声道重新分配或解码器销毁；即使随后增益改回 1 或切换排除声道，也不会重新混入已缩放的历史。AddIn `Reset()` 使用全新 FAAD 状态，所有回放复验均从同一初始条件开始。

分配、释放及声道重分配路径同时覆盖单／双声道。新增字段属于 FAAD 私有状态，不暴露给插件宿主。

## 4. 回归入口与结果

私有 `drc_cases.py` 的数值矩阵为 **48 组**：3 个时钟 × 2 种声道数 × 8 种模式（无 DRC、单位增益、×2、×0.5、排除第一声道、从 ×2 回到 1、延迟启用 ×2、播放中切换排除）。固定增益和排除模式整段逐样本符合基线乘相应增益。切换组对距边界超过三帧的稳态作精确比较，重叠边界仅检查有限性及幅度界限，避免把频域增益切换误当成瞬时时域音量切换。

跨系统入口：

```text
rebuild/tests/plugins_followup_20261030p1/aac-ltp/vmstage/run.cmd
```

该目录约 2.3 MB，使用 XP 可运行的 `/MT`、VC-LTL／YY-Thunks 探针和完整 PCM SHA256，不保存重复的输出 PCM。其 **64 条命令展开为 74 个场景**：

- 54 个 Decoder 场景：6 个实际启用预测文件 + 48 个 DRC 文件。每项还执行一次 `Reset()` 后的整段重放，要求逐位相等；54 次重放不额外重复计入场景数。
- 6 个 MP4 容器读取／Decoder 链和 2 个 7350 Hz ADTS 读取，完整 PCM 哈希一致。
- 2 个 ADTS 定位命令各含 6 个正向／反向／归零定位，共 12 个定位场景。每次定位后的全部 PCM 与连续解码相应位置逐位相同。

## 5. 保留的限制

- **真实有声 LTP960 仍待验证。** 已检查旧 FFmpeg、FAAC 1.28、此前获取的 ISO 官方样本索引及公开参考实现：上述两个可用编码器的普通 AAC 长帧均固定为 1024，当前未找到可信的实际 960 帧 LTP 音频。合法配置及共享前向变换已实现／测试，缺的是完整真实码流验收，不能直接写成未实现。
- 7350 Hz 的真实 SBR 等独立边界仍按既有明确支持范围处理，不能从核心 LTP7350 成功外推。
- 本节定位验收针对完整解码的 ADTS Reader。MP4 场景验证普通压缩 Reader 与 Decoder 的完整音频链，不将“读取到某个压缩包”误写成所有宿主均已重建此前预测状态。
- 测试工具中出现的旧编码器仅用于私有验证，不作为生产构建依赖，不重新引入其运行库或分发文件。
