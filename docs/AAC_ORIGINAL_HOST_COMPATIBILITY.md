# 新 AAC 插件在原版播放器中的兼容性

日期：2026-09-22。测试对象为工作区原版 `TTPlayer.exe` 5.7.9.0，宿主 Windows 11 x64，原程序及插件均为 x86。

## 结论

**新插件能够被该原版播放器加载，并已实际播放普通 MP4、裸 AAC 和此前失败的分片 MP4。**
这证明了本轮样本的原版宿主兼容性，不代表原插件所有功能与边界行为已经完全恢复。

本次使用原 `TTPlayer.exe` 的隔离副本，保留原 `ttpcomm.dll`、资源与外部 Nero 组件，
输入插件仅保留 `ttp_aac.dll`。通过进程模块列表确认加载路径，排除误用旧插件或其他输入插件。
每次运行使用独立播放列表与设置，静音播放约四秒后正常关闭，读取原程序保存的 `PlayingTime`。
原安装目录中的 AAC DLL 未替换。

| 文件 | 原插件 | 新插件 |
| --- | --- | --- |
| 普通 MP4 对照 | 播放进度 3,721 ms | 播放进度 3,721 ms |
| 裸 AAC／ADTS | 播放进度 3,771 ms | 播放进度 3,741 ms |
| 原问题分片 MP4 | 进度 0，立即结束 | 播放进度 3,761 ms |

短时播放进度的几十毫秒差别来自启动、观察及关闭时间，不用于判断 PCM 一致性。
该轮验证的是原宿主实际加载和播放推进，没有将四秒检查写成原宿主全曲、seek、属性编辑或转换的完整验收。
两个插件均由原程序正常退出，退出码均为 1；没有强制终止或捕获到错误对话框。

测试二进制 SHA-256：

- 原播放器：`c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`。
- 原插件：`49195708ba9b942edd8215ffcb4e5db73a1548b0c02a5e2b11960ea12af69135`。
- 新插件 0.1.0：`95e28b7b68db61b07f40612a016fdc25a018239e3b4869914e5fa3ca43b3c5ff`。

## 与原插件一致到什么程度

此前在同一测试宿主中，AAC-LC、HE-AAC、HE-AAC v2、多采样率与六声道样本的完整 PCM
字节数和摘要均与原 DLL 一致；Nero 编码的对照样本也已验证。接口恢复包括导出、GUID、
creator 顺序、虚表、调用约定及跨模块内存所有权。

仍存在明确差异：

- 新增本地分片 MP4 支持，修正原插件无法播放该容器的问题。
- 新插件处理较小输出缓冲，避免原六声道定位后不输出的情况。
- 普通 MP4 标签已在 2026-10-19 改为最后释放时写回，另有可选提交结果接口，见 [当前验证](VALIDATION_20261019.md)。
- 已支持不可定位 ADTS 流及宿主参考时长；不支持任意网络 MP4/DASH。
- ADIF、AAC Main/SSR/LD、MP3-in-MP4 等尚缺完整代表性样本对照。
- 损坏文件的错误码、全部文件属性／封面编辑、原版转换窗口的完整调用流程尚未逐项确认。

因此可以称为“已在原版 5.7.9 验证主要本地播放路径的兼容插件”，不能称为“所有原插件行为完全相同”。
新插件需要 SSE2。XP 虚拟机恢复后，已补齐 XP SP3 x86 的实际验证，见下节。

## XP 补充实测

在 XP 已登录桌面，原版 5.7.9 使用新插件播放普通 MP4、裸 AAC 和问题分片 MP4，
约四秒后的保存进度分别为 3,940／3,930／3,930 ms；旧插件普通 MP4 为 3,910 ms，分片 MP4 为 0。
进程模块路径已确认，均正常关闭，无错误对话框或强制结束。
旧插件对照依赖的 VC++ 2012 x86 运行库只补入隔离目录，新插件无需该依赖。
重建版 XP／Win7 使用同一新插件也已实际播放问题文件。
