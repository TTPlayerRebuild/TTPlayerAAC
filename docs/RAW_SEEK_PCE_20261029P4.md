# 原始 AAC 定位、取消恢复与 PCE 声道配置

日期：2026-10-29；构建批次：2026.10.29p4。

## 已复现的问题

对同一个真实 ADTS 文件先连续解码，再执行 `Seek(0)`，p3 输出多出一帧。以 48 kHz 双声道 LC 为例，连续播放输出 770,048 字节，定位到开头后输出 778,240 字节，相差 8,192 字节，即 1,024 帧 float 双声道 PCM。非零定位也出现样本偏移，HE／HEv2 的滤波历史以及 Main／LTP 的预测状态不能靠一帧预热恢复。

原实现执行 `NeAACDecPostSeekReset`，跳到目标压缩帧，并仅解码其前一帧。这个过程不能恢复与连续播放相同的状态，也没有保持统一的首帧 PCM 坐标。

另一个独立问题是合法 ADTS 的 `channel_configuration=0`：声道配置在帧内 PCE 中提供。`NeAACDecInit` 尚未解码 PCE，会暂时返回零声道；旧适配层在此提前拒绝，导致由真实 Main／LTP MP4 无损重封装得到的 ADTS 无法打开。

## 实现

- 为本地原始流记录已消耗的 PCM 帧数。向前定位沿用当前解码器和未消费 PCM；向后定位建立新解码器，从起点恢复完整历史。
- ADTS 保留压缩帧粒度定位，但所有目标都映射到连续播放的 PCM 原点；ADIF 保留按输出采样点定位。
- 只保留当前压缩读取缓冲和 PCM 缓冲，不缓存整首歌曲的解码结果。到达文件尾返回实际可用位置。
- 定位发生取消时保留目标。下次有效读取重新恢复历史；新一次定位可以替换该目标。无效输出容量不消耗数据，取消返回的输出长度为零。
- ADTS 核心频率在打开时缓存；定位不再为计算目标额外读取文件头。
- 仅对合法 ADTS 的 PCE 配置允许初始化时声道数暂为零。首个有 PCM 的帧完成声道发现后才发布格式；最终格式仍严格要求有效采样率和非零声道。

接口与导出不变。此修正消除错误行为，不声称复制原版所有解码器的缺陷。普通 MP4 压缩 Reader、MP4 编辑时间轴、标签和封面保存继续走各自路径。

## 回归设计

私有测试位于 `rebuild/tests/plugins_followup_20261029p4/aac-seek`。样本包括 LC 单声道、双声道、六声道、96 kHz，以及 HE、HEv2、Main、LTP，均以真实编码包重封装为 ADTS，没有靠修改采样率或类型位假装真实样本。

每个样本验证 25 组，共 200 组：

1. 六次从零、非零、向前、向后及重复位置开始读取完整尾部，与连续播放对应片段逐字节比较。
2. 16 种取消组合：`E_ABORT`／`ERROR_CANCELLED`，已返回 0／7 字节，一次／两次取消，恢复读取／替换目标。包括错误输出容量及 Stop／Start 后重试。
3. 两次前向定位后用非对齐容量读取，确认只返回完整采样帧且 PCM 一致。
4. 未知长度实时 IStream 完整解码与本地流输出比较，包括帧内 PCE。

最终系统、宿主与发行文件验证见 [p4 汇总](../../rebuild/docs/AUDIO_PLUGIN_FOLLOWUP_20261029P4.md)。测试不进入 Actions、运行 ZIP 或源码附件。

独立的连续解码对照还确认：Main ADTS 的 5,780,480 帧、LTP ADTS 的 911,360 帧，与对应 MP4 以及此前冻结的参考 PCM 均逐位相同，排除了仅在同一错误结果上比较定位的可能。

## 性能与剩余范围

向后定位需要从头解码到目标，时间随目标位置增长；这是恢复预测、噪声及 SBR 历史的成本。向前定位只补充剩余历史，内存不随歌曲时长增长。后续可设计经验证的解码状态快照，但不能用固定一帧预热代替。

ADIF VBR 时长仍是码率估算；未知长度输入不可随机定位。Main 耦合通道、SSR 和 LD480 有声组合等未因本次修正自动完成，见 [剩余 Main／SSR 分析](MAIN_COUPLING_SSR_REMAINING_20261029P4.md)。
