# AAC SSR 恢复与一致性验证（2026-10-30）

本轮实现 AAC SSR（Audio Object Type 3）的四子带逆变换、增益恢复、窗与重叠、IPQF 合成以及状态复位。没有将 LC 改写为 SSR 作为正样本，也没有继续采用忽略增益控制的旧实现。新增算法静态编入现有 FAAD2 2.11.4 私有副本，不引入 Rust 或其他运行时 DLL。

## 依据和可靠参考

- [ISO/IEC 14496-3:2009](https://csclub.uwaterloo.ca/~ehashman/ISO14496-3-2009.pdf) 的 §4.6.12 给出 SSR 解码流程；§4.5.1.1（PDF 第 530 页、正文第 54 页）明确 SSR 的 `frameLengthFlag` 必须为 0，使用 256/32 线子带 IMDCT。因此拒绝所谓 SSR960 是检查不合规范配置，不是遗漏一个合法 SSR 帧长。
- [ISO 官方 Part 26 第 2 版电子附件](https://standards.iso.org/iso-iec/14496/-26/ed-2/en/) 提供 `compressedMp4.zip`、`referencesWav.zip` 和官方 MD5 清单。其 `doc.zip/fileNameConventions.html` 明确 `as` 前缀为 AAC SSR。本轮通过 HTTP Range 获取所需原始成员、逐项核验官方 MD5；没有修改编码内容或参考 WAV。
- 获取 20 个真实 SSR MP4：`as00_44`～`as17_44`，另有 `as01_08` 和 `as01_96`；ASC、FFprobe 和实际增益语法均确认 SSR，覆盖 8、44.1、96 kHz 和单/双/6/8 声道。
- 公开 [oxideav-aac](https://github.com/Sec-ant/oxideav-aac/tree/5e71c7556f4b7691bbf8aa7306331e8fb5976ef1) 的增益公式/IPQF 作为额外源码交叉检查。固定 commit 为 `5e71c7556f4b7691bbf8aa7306331e8fb5976ef1`。本实现使用固定 C 数组及 FAAD FFT；相关 MIT 版权许可保留在 `third_party/SSR_REFERENCE_NOTICE.txt`。最终音频正确性以 ISO 原始参考 WAV 为准，不以这个实现的自测声明为准。

## 修复内容

| 原有问题 | 本轮实现 |
| --- | --- |
| `SSR_DEC` 未启用，CPE 申请缓冲区使用不存在的 `cpe` 变量，`MUL_R_C` 无定义 | 修复禁用分支的编译/链接与声道作用域，再启用 SSR |
| `ssr_gc_function` 全部返回 1，忽略传输的增益 | 按各窗解析的 `aloccode/alevcode` 重建指数插值 FMD，组合跨帧 PFMD 和 GMF，应用倒数增益；无分配或可变全局状态 |
| 256/512 临时区 stride 不一致 | 每个子带固定 256 频域值、512 未重叠时域值，重叠区每带 512，输出每带 256 |
| 短窗取频谱列错误、右半窗方向错误、所有左半窗误用前帧形状 | 按窗口优先的频谱提取每个 32 线子带，奇数子带反序；仅第一个短窗左半继承前帧形状，右半正确反向 |
| 短窗前出现普通长窗时沿用全部长窗尾部 | SSR 只保留所需短窗重叠片段，清除 144～255 段；由 ISO `as17_44` 的随机窗切换实际暴露并验证 |
| IPQF 首次调用全局无锁分配、系数指针共享 | 96-tap 原型生成不可变系数表，每个 decoder 保留独立 4×24 历史；没有锁或新系统 API |
| PFMD 用 -1 初始化、定位没有清理 SSR 状态 | PFMD 初始为 1，重叠/IPQF 初始为 0；PostSeekReset 清理每声道历史；公开 Decoder 的全状态重建由统一修复处理 |
| 8 kHz SSR 被默认当作隐式 SBR 输出 16 kHz | ASC 和原始流只对 SSR 停止该猜测；保留原 LC/HE 行为；拒绝 SSR 的显式或带内 SBR |
| 错序/越界增益位置没有语义检查 | 在时域重建前检查增益位置顺序、窗口终点和范围，损坏配置明确返回错误 |

四个新增私有适配文件为 `cmake/faad2_ssr_compat.cmake`、`faad2_ssr_core.c`、`faad2_ssr_filterbank.c`、`faad2_ssr_ipqf.c`。补丁作用于构建树中的 FAAD 副本。源分发应包含这些适配源和版权声明，测试代码和 ISO 样本仍不进入仓库、Actions 或发行包。

## 本机私有验证与公共接口

核心 123 项检查通过：20 份完整解码、重播前清理 SSR 状态、每份 4 个并行解码实例各重开 3 次，以及错序增益、窗口越界增益和不合规范 SSR960 配置。并发结果与单实例逐位一致。该核心探针采用 x86/SSE2、VC-LTL 和 YY-Thunks；没有借本机 Python/Rust 运行时提供插件运行能力。

公共接口验证使用独立加载参数指定的最终 `ttp_aac.dll`，包括工厂 0 的 MP4 Reader → 工厂 2 Decoder、独立 Decoder、工厂 1 ADTS Reader。没有 edit/gapless 的 MP4 Reader 仍按原 ABI 输出压缩 AAC，其 Format 中 16-bit 占位并不代表错误的 PCM 位深；必须经过 Decoder 后比较 float PCM。

8 声道 ISO 向量的 PCE 是 5 front + 2 back + LFE。FAAD 仅给重复的 FL/FR 标签，MPEG 次序实际为 FC/FLC/FRC/FL/FR/BL/BR/LFE；宿主输出应按 Windows 次序重组为索引 `[3,4,0,7,5,6,1,2]`。原始 ADTS 的在带 PCE 还必须真正启用，不能仅解析后丢弃 `pce_set` 而猜成另一种八声道布局。这两项由统一宿主适配修复，并由公共探针单独验收。

本机统一 DLL SHA256 `68c95cb8b51fd0efcb75510cb33dcdcead455918334058bd96b6e28981f6f4bf` 的 **55 组公共接口检查全部通过**：20 份独立 Decoder（各含 Reset 后精确重播）、20 份 MP4 Reader → Decoder、7 份 ADTS Reader（各含 0/500/2000 ms 定位后与顺序播放精确比较）、6 项不合规范/损坏边界，另加合法 LTP960 的仅 ASC 初始化接受和 Initialize 同一输入/输出缓冲的兼容验证。所有有效 PCM 与上表已对照 ISO 参考的结果逐位一致；8 声道正确的 Windows 重排单独核验。

`vmstage/run.cmd <最终 ttp_aac.dll 的绝对路径>` 会直接加载参数指定的 DLL，运行 55 组公共工厂测试，以本机已经独立核验的完整 PCM 哈希检查输出，不依赖 Python、Rust、FFmpeg 或私有核心 DLL。目录约 8.53 MB。本机平铺 stage 复跑结果为 `AAC_SSR_CASES=55 FAILURES=0`。XP/Win7 的最终运行结果由统一收尾记录补充；不把只链接私有核心的通过结果冒充最终 DLL 在虚拟机中的通过结果。

## 最终审查补充

启用上游 SSR 宏时，其旧 `mp4.c` 用 AOT 4 误判“SSR 不允许短帧”，会错误拒绝合法 LTP960。本补丁将判定改为 `SSR` 常量，并同时验收 SSR960 拒绝与 LTP960 ASC 初始化接受。LTP960 这项仅验证配置入口，不冒称完成有声参考验证。

统一 Decoder 失败初始化清理起初会在 `in == out` 时提前清零输入头。本轮通过原版公开工厂确认同一缓冲的 LC44100 初始化有效，统一修复先复制输入头再清空输出；第 55 组公共检查覆盖该原版兼容行为。
