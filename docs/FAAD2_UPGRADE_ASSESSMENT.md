# FAAD2 2.11.3 升级评估

日期：2026-09-22。下文保留从 FAAD2 2.7 升级的隔离评估记录。
当前已升级至 2.11.4，见 [2026-10-19 验证](VALIDATION_20261019.md)；本页历史数据不作为当前 DLL 的复测结论。
**后续已按用户要求正式采用 2.11.3，并改为构建时下载固定归档。**
依赖源码不提交 Git，仓库保留完整许可和适配脚本，Release 另附对应源码包；见 [许可与分发](LICENSING.md)。

## 结论

**可以升级。** 已把 FAAD2 2.11.3 与现有插件封装组合，使用现代 MSVC、VC-LTL、YY-Thunks
构建 x86 DLL，并通过本机及 XP／Win7 虚拟机的既有样本检查。

主要取舍是：新版修复了多项解码问题，但输出不再与 FAAD2 2.7／原版插件逐字节一致。
本次 12 组 PCM 结果中，11 组哈希变化，所有输出字节数保持一致。
这不是 11 个独立格式：其中包括同一音频的普通 MP4、分片 MP4、ADTS 和小缓冲重复对照。

正式采用 2.11.3 后，目标为“保留原插件接口与播放器行为，使用更新的解码核心”。
如果验收必须包含与原版完全一致的 PCM，则不能把这次升级当作无行为变化的替换。

## 上游版本与收益

核对时，上游最新正式版为 [FAAD2 2.11.3](https://github.com/knik0/faad2/releases/tag/2.11.3)。
该版本修复了 SBR、频谱反量化、Huffman、预测等路径中的多项越界、溢出和空指针问题。
发行说明中还有命令行前端 MP4 解析修复；本插件使用自己的 MP4 reader，不能将这些前端修复算作本插件容器层的收益。

当前封装调用的 `NeAACDecOpen`、`NeAACDecInit`、`NeAACDecInit2`、`NeAACDecDecode`、
配置查询和 seek reset 接口在新版仍存在。见 [2.11.3 接口头文件](https://github.com/knik0/faad2/blob/2.11.3/include/neaacdec.h)。
无需因此改写插件的四类 creator、COM 接口、MP4 标签／封面实现或 Nero 适配层。
升级解码库本身不会自动补齐本插件尚未支持的网络流、DASH、DRM、分片 MP4 标签写入等功能。

## 接入调整

隔离工程沿用正式版本的 x86、C++17、SSE2、`/O1 /Ob2 /Os`、链接时优化、`/fp:precise` 和浮点输出。
仅在构建目录内生成适配副本，保留上游下载源码及正式 2.7 源码：

1. 新版要求提供 `PACKAGE_VERSION`；另设置 `FAAD2_VERSION` 为 `2.11.3`。
2. 明确启用 `APPLY_DRC=1`，保留原解码核心执行动态范围控制的配置。
3. 新版 Windows API 宏默认声明 `dllexport`；静态内嵌时去掉该导出修饰，使最终 DLL 仍只导出 `ttpGetSoundAddIn`。
   新版宏位于返回类型之前，不能直接照搬旧头文件的 `__cdecl` 宏替换。
4. 对 MSVC x86 的内联 `lrintf` 延续私有命名及先包含 `<math.h>` 的适配，保留其 x87 取整实现。

版本宏、DRC 选项等配置依据见 [上游 CMakeLists.txt](https://github.com/knik0/faad2/blob/2.11.3/CMakeLists.txt)。
本次未引入新的运行时 DLL，也不需要重新安装 VS2019 或 v141_xp。

## 构建与系统结果

| 项目 | 正式 FAAD2 2.7 | 隔离 FAAD2 2.11.3 |
| --- | ---: | ---: |
| DLL 字节数 | 350,208 | 369,664 |
| DLL 大小 | 342 KiB | 361 KiB |
| 静态系统 DLL 数 | 3 | 3 |
| 静态导入数 | 75 | 90 |
| PE 子系统版本 | 5.01 | 5.01 |
| XP／Win7 静态导入检查 | 通过 | 通过 |

体积增加 19 KiB，约 5.56%。这只是相同体积优化选项的对照，不宣称新版已达到最小可能体积。
新版实际导入仍为 KERNEL32、OLE32、系统 MSVCRT，未增加 VC++ 2012 依赖。

本机、XP SP3 x86、Win7 SP1 x64 均通过：

- 普通／分片 MP4、ADTS，48／96 kHz、低采样率、单声道、HE-AAC、HE-AAC v2、六声道解码至 EOF。
- 开头／中间／末尾定位，分片 MP4 的 4,000 字节缓冲读取。
- 普通 MP4 Unicode 标签及 PNG 封面写入／重开／删除、裸 AAC 标签操作。
- 外部 Nero 组件编码、完成文件及使用新解码器重读。

两台虚拟机各 12 组 PCM 字节数／哈希与本机的新核心结果一致；回收的 DLL 哈希也一致。
这些是测试宿主调用实际插件接口的结果。本轮未重做原版播放器 GUI 全流程、Nero 配置窗口、
全部损坏码流或模糊测试，不能据此承诺所有文件的解码结果与质量。

## PCM 差异

浮点音频以约 ±1 的幅值表示；下表比较同一文件完整解码的逐样本绝对差值。

| 样本 | 最大绝对差值 | 差值均方根 |
| --- | ---: | ---: |
| 原问题分片 MP4 | 2.3842×10⁻⁷ | 2.2353×10⁻⁹ |
| HE-AAC | 2.9802×10⁻⁷ | 2.8919×10⁻⁸ |
| HE-AAC v2 | 4.6673×10⁻⁷ | 3.2679×10⁻⁸ |
| 48 kHz | 0.00115391 | 0.0000379192 |
| 96 kHz | 0.00170204 | 0.0000495038 |
| 低采样率 | 0.00133790 | 0.0000447905 |
| 单声道 | 0.00123749 | 0.0000188766 |
| 六声道 | 0 | 0 |

原问题音频与 HE 样本的数值差异很小，但部分其它样本的差异更大，不能全部归为最后一位浮点舍入。
哈希变化本身也不能证明音质变差或变好；没有进行听感盲测。
Nero 编码重读的 PCM 哈希变化只说明最终解码结果变化，本轮未据此判断编码器输出是否变化。

正式 DLL 为 369,664 字节，SHA-256：
`80e30c42f647de03dc99272c7d9f76350891da2f843fcc1c2af45458d29762d7`。

定位、普通 MP4 标签／PNG 封面、裸 AAC 标签、Nero 编码重读检查通过。

Win7 为 3,410 ms；均确认实际模块路径，未出现错误对话框，正常关闭。
