# 显式采样时钟、PCE 与 Decoder 重置修复

日期：2026-10-30。适用于同一份 x86、SSE2、VC-LTL／YY-Thunks 构建，保持原版 AddIn 公共接口。

## 显式采样率

之前只接受频率表中的值，表外 ASC 频率直接失败。现按 ISO 的采样率区间选择频谱表族，并在解码器私有状态中单独保存真实时钟。输出格式、时长和定位均使用真实频率，不把 50000 Hz 伪装成 48000 Hz。MP4 的 16.16 提示频率为零时，也可从 ASC 恢复时钟。

私有测试以真实编码的 AAC-LC 音频为基础，在同一个标准频谱表族内修改时钟，并同步重建 ASC、MP4 时间轴、编辑列表；压缩频谱未伪造。覆盖 7000、7349、7351、10000、13000、20000、26000、30000、50000、72000、90000、100000、192000 Hz，普通／零提示字段容器、独立 Decoder、完整 Reader PCM 与反向定位共 65 组。

FFmpeg 9.0.1 的 AAC 解码器拒绝这批显式 index 15 配置，因此独立参考比较使用相同表族的原始编码时钟；时钟与时间轴正确性另由公共接口检查。不能把这项验证描述成 FFmpeg 直接解码了所有表外频率。完整 PCM 最大绝对误差不超过 3.2e-7；Reader 与 Decoder 输出逐位一致。

此前将这些配置判为非法的 ASC-only 测试，现明确改为初始化及实际时钟检查。它们原来仅改写了 44.1 kHz 数据的头部，并非新频率下的有效有声音频；新的完整解码样本单独覆盖正向行为。零频率、保留索引、截断字段和无实现依据的 SBR 组合仍应报错。

## ADTS 声道布局

原 FAAD2 解析在带 PCE 后没有启用它。对于 `channel_configuration=0` 的 ADTS，解码器退回按声道数量猜测位置：官方 8 声道 SSR 样本实际为五前方、两后方、一个低频，原输出被错误描述为四前方、三后方、一个低频，公共封装因此拒绝播放。

现仅在 ADTS 的配置为零时启用成功解析、与 Profile 和采样率一致的 PCE。MP4 已由 ASC 声明配置，仍按其配置处理，不以访问单元中的 PCE 覆盖。SCE 与 LFE 的 tag 使用不同映射，避免中心声道与低频声道同为 tag 0 时互相覆盖。

FAAD 对两对前方声道均标为 FL／FR。封装按四／五前方布局恢复第一对 FLC／FRC，再按 Windows speaker mask 排列；不会丢弃声道或把两对混为一对。五前方布局的约定亦可核对 [FFmpeg AAC 通道表](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavcodec/aac/aacdec_tab.c) 和 [通道分配实现](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavcodec/aac/aacdec.c)。

## Decoder 生命周期

原 `Reset` 只调用 `NeAACDecPostSeekReset(-1)`，没有重建预测、重叠、噪声与滤波状态，也保留帧计数。有效 CCE 测试中，重播从 90112 字节变成 98304 字节，多了一帧，PCM 也不一致。

现独立 Decoder 保存成功初始化所需的 ASC，Reset 时建立全新解码状态，同时保留已经确认的 PS 立体声提示。原始 Reader 的定位重放路径不变。合法指针但无效配置的重新 Initialize 会清除就绪状态和旧缓存，避免初始化失败后仍输出上一个文件的数据；随后可用有效配置恢复。

原版公开接口还允许 `Initialize(format, format)`。清理输出前先保存输入头，扩展配置仍从原缓冲读取；同缓冲初始化与失败后恢复均有专门回归，未用清理旧状态破坏原版宿主的复用方式。

## 验证边界

- 新支持的是真实 AAC 核心时钟，非任意 SBR 重采样器。7350／14700 Hz SBR 与表外核心频率的 SBR 仍受控拒绝，未以近似表族冒充高频重建。
- 公共旧接口仍一次声明固定 PCM 格式；未增加动态切换采样率／声道的协议。
- 全部探针、样本与独立参考留在 `rebuild/tests/plugins_followup_20261030`，不进入 Actions 或发行源码仓库。
