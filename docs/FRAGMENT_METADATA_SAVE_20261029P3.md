# 分片 MP4 标签与封面保存：2026.10.29p3

本次补齐本地分片 MP4 在**现有元数据区／预留空间足够**时的标签、封面写回。不会搬移音频分片或重新计算媒体索引；空间不足会返回真实错误并保持文件不变。普通 MP4 的追加 `moov` 保存路径不变。

## 原因与恢复范围

原插件的 MP4 Reader、采样表与相关 ABI 证据见 [重建可行性分析](AAC_PLUGIN_REBUILD_FEASIBILITY.md)；原分片文件的播放限制见 [分片 MP4 分析](FRAGMENTED_MP4_AAC_ANALYSIS.md)。分片支持本身是重建版的扩展，本次没有把新增写回能力宣称为原插件已有行为。

此前重建实现有两层硬性拒绝：Reader 打开分片后取消可写标志；`Mp4File::save` 再次返回 `E_ACCESSDENIED`。即使文件包含充足的 `free` 空间，也不能保存标题或封面。

普通 MP4 可以把新 `moov` 放在文件末尾并退休旧索引。分片容器还有初始化信息与 `moof` 的顺序，以及 `tfhd`、`trun`、`sidx`、`tfra` 等定位关系，不能未经验证直接套用该移动策略。本次采用原位置、固定总长度的局部更新。

## 更新方法

1. 优先选择现有元数据所在的 `udta`，或直接位于 `moov` 的 `meta`。重建其中的 iTunes `ilst` 标签与 `covr` 封面，保留其它不认识的元数据内容。
2. 可利用所选元数据内部的 `free/skip`，以及紧接该区的同级 `free/skip`。其它 `udta`、其它根 `meta` 和其它根节点保持原位置与原字节。
3. 没有元数据时，使用现有根预留区创建 `udta/meta/ilst`。如果预留区位于 `moov` 之后且紧邻它，可将这段空间纳入 `moov`，只扩大 `moov` 头声明的范围。
4. `trak`、各 sample 的偏移／长度／时间／composition、`moof`、`mdat`、`sidx`、`mfra/tfra` 均不搬移；文件长度不变。扩展尺寸的 16 字节 `moov` 头也受支持。
5. 剩余空间写为合法 `free`。剩余 0 字节或至少 8 字节可保存；剩余 1～7 字节无法表示一个 box，本版返回 `STG_E_MEDIUMFULL`，不会写入非法短尾部。

保存前核对文件长度、原 `moov` 的完整字节；吸收外部预留区前还逐个核对其原始 8／16 字节 box 头。如果它已被其它写入者同长度替换，返回 `STG_E_REVERTED`，不覆盖改变后的结构。

## 错误与接口语义

| 情况 | 行为 |
|---|---|
| 现有槽足够 | 局部写入元数据区；必要时更新 `moov` 头；提交成功后更新内存快照 |
| 容量不足或残余 1～7 字节 | `STG_E_MEDIUMFULL`；不调用写入，文件字节不变 |
| 普通部分写入／头写入失败 | 恢复原元数据槽与原 `moov` 头，再提交恢复；返回原写入错误 |
| 提交失败，后续写入恢复成功 | 恢复到保存前字节，返回原提交错误 |
| 恢复自身仍失败 | `STG_E_REVERTED`；不宣称文件已可靠恢复 |
| 打开时指定只读 | 仍不公布可写位，设置标签返回 `E_ACCESSDENIED` |

Reader 的 capability 位 4 表示该打开方式允许尝试元数据保存，不表示任意长度的标签／封面都必然装得下。调用方应检查可选 `MetadataCommit::Commit()` 的真实结果。

原 ABI 不变。旧宿主没有提交接口时，仍在最后一个 Reader 引用释放时保存，但旧接口无法把保存失败结果返回给宿主。已有可选提交接口是一轮编辑的终点：重复 Commit 返回第一次结果；提交后继续修改返回 `E_UNEXPECTED`，失败后重试也应重新打开 Reader。本次对这条行为进行了测试。

底层 `Mp4File` 的成功保存会更新其元数据快照，直接使用该内部对象可以继续缩小／增长标签；这不改变公开 Reader 的终结提交约定。保存不追加文件，所以重复保存不会使分片文件持续膨胀。

这是可恢复的局部写入，不是断电事务。持续介质故障、进程在覆盖中被强制终止、无锁并发写入均不承诺事务原子性。在线 DASH、DRM、任意无预留空间的分片重排仍不在本次范围内。
